How Plan Challenge works

One idea in. A fresh AI reviewer attacks the plan. Every issue gets a logged decision. A revised plan comes out. Nothing is built.

One run, step by step

1You ask Claude Code or Codex chat /challenge <idea> in Claude Code, $challenge <idea> in Codex. An existing plan file or the current discussion also works.
→
2The writer drafts plan-v1.md Goal, constraints, non-goals, steps and success checks. At most 500 words. Secrets are removed. This draft is kept untouched.
→
3Pick the reviewer routing.py (no model call)
  • Routine plan: Codex
  • Money, safety, public or hard to undo: it asks you. Claude, both, or stay with Codex
  • A reviewer you name is always used
→
4Fresh review review.py + critic-prompt.md
  • Starts in a new empty folder
  • Tools switched off
  • Sees only the plan and the rubric, never the chat
  • 180 s time limit
→
5Format check validate() in review.py A verdict line, at most 5 issues, each with severity, failure and fix. At most 400 words.
Fails: marked NOT CHALLENGED. Raw reply kept. A review is never invented.
passes ↓
6Decide on every issue decisions.md One row per issue: accept or reject, with one reason. No issue is skipped. Fixes outside the brief are rejected.
←
7Revise the plan plan.md The accepted fixes are applied. The first draft stays next to it, so before and after can be compared.
←
8One recheck, if needed critique-<reviewer>-2.md Only when round one raised a blocker. Same reviewer, revised plan, once. A blocker still open is reported, not hidden.
←
9Stop and report three short lines The run folder, the verdict and the main changes. The skill stops here and waits for you before any code is written.
What is left on disk challenge/<name>/ plan-v1.md, each critique with its usage file, decisions.md and plan.md. A full record of what was raised and why it was accepted or not.

Three ways to run it

Default: one reviewer One call, plus one recheck if there was a blocker. Codex at low effort unless you choose Claude (medium effort).
both: two opinions Codex then Claude, once each, on the same untouched draft. Neither sees the other's review. If one fails the result is marked PARTIALLY CHALLENGED.
measure: compare them Each reviewer runs twice. Issues are merged and shown shuffled with no names. You accept or reject each one, then the names are revealed and counted.

How it was tested, and where things live

A benchmark with planted flaws, run live on both reviewers and graded blind. Every raw reply is in the repo.

The benchmark pipeline

A12 plans, frozen evals/plan-review/ Six pairs: one plan with 2 planted flaws, and its twin with the flaws repaired. Plans, answer key and scoring rules were committed before the first call.
→
BRun both reviewers run_benchmark.py → runs/ Each reviewer reads each plan twice: 48 live calls through the same review.py. Saves the reply, tokens, time, file hashes and CLI versions. Failures are kept, not rerun.
→
CHide the names score.py blind Reviews are copied under random names and shuffled. The key that maps them back stays out of the grader's view.
→
DGrade each finding judgments.jsonl An AI grader writes one row per finding with a reason: planted flaw found, old flaw wrongly repeated, valid extra, or unsupported.
→
ECount score.py report Flaws found, false alarms on repaired plans, tokens, time, and a replay of four routing policies on the same reviews.

The decision this led to
Codex reviews every plan: fast and reliable. Claude is offered when a mistake would be expensive: about twice the extra findings that held up.

Read the numbers with these limits

  • The plans are synthetic and were written with AI help. Twelve is a small set.
  • The grader is an AI and no person checked its rows. Two blind passes agreed on 47 of 55 findings.
  • Both reviewers hit the ceiling on planted flaws, so the test does not say which one catches more blockers.
  • Dollar cost is unknown for Codex. Its CLI does not report it.
  • The format check was loosened after the benchmark. The numbers were not recomputed.
